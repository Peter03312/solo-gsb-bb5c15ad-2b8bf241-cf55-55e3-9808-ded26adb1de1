# 水质实验室 · 样本分装与混样溯源工作台

面向水质实验室的样本分装 / 混样登记与溯源 Web 工作台：登记原始样本瓶、记录每次分装混样操作、实时追踪每个瓶的余量与完整来源谱系，并支持对历史操作的安全更正。

- **后端**：Node.js 20 + Express
- **数据库**：SQLite（[better-sqlite3](https://github.com/WiseLibs/better-sqlite3)，同步事务，WAL 模式）
- **前端**：原生 HTML / CSS / JavaScript 单页，无需构建

## 功能一览

| 能力 | 说明 |
| --- | --- |
| 原始瓶登记 | 录入瓶编号、采样时间、以毫升计的初始体积（正整数） |
| 分装 / 混样操作 | 唯一操作号、目标瓶编号、操作时间、一个或多个来源瓶及各自正整数取用量；目标体积自动取取用量之和，目标瓶在操作提交时自动生成 |
| 体积守恒 | 所有校验在一个 SQLite 事务内通过“按操作时间顺序重放”完成，任一时点都不允许超用 |
| 并发安全 | 数据库事务串行化写入 + 全量重放校验，并发争用同一来源瓶不会超扣；同一操作号重复提交（相同内容）幂等返回，**绝不重复扣量** |
| 历史更正 | 修改历史操作的时间 / 来源 / 取用量后按操作顺序整体重算；若后续操作因此超用，**整次更正被拒绝并逐条指出冲突的操作号、来源瓶与缺口毫升数，原数据保持不变** |
| 余量展示 | 每个瓶的出生体积、累计取用与当前余量 |
| 完整来源谱系 | 沿操作来源递归向上追溯，展示任意瓶的全部祖先瓶、经由操作号、操作时间与取用体积 |
| 明确报错 | 瓶编号冲突、目标编号冲突、来源不存在、同一操作内来源重复、取用量非正整数、操作时间早于来源采样/创建时间、超用等均有独立错误码与中文说明 |

## 一键启动（Docker Compose）

前置要求：已安装 Docker 与 Docker Compose 插件（`docker compose version` 可用）。

```bash
docker compose up --build -d
```

启动时会自动：

1. 构建镜像并 `npm install` 安装依赖（better-sqlite3 如无预编译二进制会在镜像内源码编译）；
2. 初始化 SQLite 数据库与全部表结构（`/app/data/lab.db`）；
3. 首次启动写入一份演示数据（3 个原始瓶 + 3 次分装混样操作）。

随后在浏览器访问：

> **http://localhost:3000**

停止与查看日志：

```bash
docker compose logs -f
docker compose down            # 停止（数据保留在 Docker 卷 tracebench-data 中）
docker compose down -v         # 停止并删除数据库卷（清空全部数据）
```

## 配置

所有配置通过环境变量提供，均为可选项：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 容器内监听端口；Compose 中宿主机映射端口也由根目录 `.env` 的 `PORT` 控制 |
| `DB_PATH` | `data/lab.db`（本地）/ `/app/data/lab.db`（容器） | SQLite 数据库文件路径，所在目录自动创建 |
| `SEED_DEMO` | `true` | 仅在数据库为空的首次启动时写入演示数据；设为 `false` 可得空库 |

修改对外端口可复制 `.env.example` 为 `.env` 后调整，例如 `PORT=8080`，再访问 http://localhost:8080 。

## 本地直接运行（不用 Docker）

需要 Node.js ≥ 20：

```bash
npm install
npm start
# 可选：PORT=8080 DB_PATH=./data/lab.db SEED_DEMO=false npm start
```

浏览器访问 http://localhost:3000 。

## 使用说明

1. **登记原始瓶**：在“② 登记原始瓶”页填写瓶编号、采样时间、初始体积（正整数毫升）。
2. **提交操作**：在“③ 分装 / 混样”页填写唯一操作号、新的目标瓶编号、操作时间，并添加一行或多行来源瓶与取用量；页面实时显示目标体积（取用量之和）。校验不通过时会弹窗逐条列出冲突。
3. **查看余量 / 谱系**：在“① 瓶余量”页查看所有瓶的当前余量；点某行的“谱系”按钮（或顶部下拉选择）展示该瓶递归向上的完整来源树。
4. **更正历史**：在“④ 操作记录 / 更正”页点任意操作的“更正”，修改时间、目标编号或来源取用量后提交。系统按操作顺序重算全部相关瓶：安全则生效并重算余量；若导致后续操作超用，整次拒绝并指明冲突记录，原数据不变。

## 业务规则

- 取用量与初始体积均为**正整数毫升**；目标体积 = 各来源取用量之和。
- 同一操作内**来源瓶不得重复**。
- 按操作时间升序逐笔扣减（同一时刻按操作录入顺序），来源瓶在该时点的余量不足即判定**超用**并拒绝该操作。
- 操作时间**不得早于任一来源瓶的采样时间（原始瓶）或生成时间（派生瓶）**。
- 瓶编号全局唯一：目标瓶不得与任何现有瓶重名，原始瓶编号不得重复登记。
- 更正历史操作时采用“替换该笔 + 全量重放”的方式校验；任何冲突都会导致事务回滚。

## HTTP API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/health` | 健康检查 |
| `GET` | `/api/bottles` | 瓶列表与当前余量 |
| `POST` | `/api/bottles` | 登记原始瓶 |
| `GET` | `/api/operations` | 操作记录列表（按操作时间排序） |
| `POST` | `/api/operations` | 提交分装 / 混样操作（同操作号同内容重复提交幂等） |
| `PUT` | `/api/operations/:opNo` | 更正历史操作（整体重算，冲突则 422 拒绝） |
| `GET` | `/api/bottles/:code/lineage` | 单瓶详情与递归来源谱系 |

提交操作请求体示例：

```json
{
  "opNo": "OP-20261004-01",
  "target": "MIX-D",
  "operatedAt": "2026-10-04T09:30",
  "sources": [
    { "source": "RAW-001", "amountMl": 100 },
    { "source": "RAW-002", "amountMl": 50 }
  ]
}
```

校验失败统一返回 4xx 与结构化错误，例如超用：

```json
{
  "error": {
    "code": "OP_REJECTED",
    "message": "操作 OP-20261004-01 校验未通过：1 处冲突",
    "conflicts": [
      {
        "code": "OVERDRAFT",
        "opNo": "OP-20261004-01",
        "source": "RAW-001",
        "conflict": { "requestedMl": 100, "availableMl": 40, "shortfallMl": 60 },
        "message": "操作 OP-20261004-01 从 RAW-001 取用 100 ml，超过该时点可用余量 40 ml（缺口 60 ml）"
      }
    ]
  }
}
```

## 测试

仓库自带两个零依赖的端到端脚本（对运行中的服务执行）：

```bash
# 功能：登记/操作/各类报错/历史更正拒绝/谱系
BASE=http://localhost:3000 node test/api.test.js
# 并发：20 并发争用同一来源瓶、同一操作号并发重复提交
BASE=http://localhost:3000 node test/concurrency.test.js
```

> 注意：两个脚本都会写入测试数据，建议在一次性空库（`SEED_DEMO=false`）实例上执行。
